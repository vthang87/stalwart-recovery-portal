Stalwart Recovery Portal

Custom extension cho Stalwart, chỉ bổ sung recovery email, OTP và password recovery. Không xây lại các chức năng quản trị mail đã có trong Stalwart.

Nguyên tắc: Stalwart là source of truth cho principal, password, authentication, role và permission. SQLite chỉ lưu recovery metadata, OTP challenge và audit.

1. Scope

  • User login qua Stalwart.
  • Add/change/verify recovery email.
  • Forgot Password → OTP → new password → update Stalwart.
  • Change Password cho user đã login.
  • Recovery Admin: tìm Stalwart principal, set recovery email, resend verification, revoke challenge, xem audit.
  • SMTP generic với tài khoản noreply.
  • Docker image độc lập.

4. Auth & RBAC

Portal không có user/role database riêng. Login được authenticate bằng Stalwart. Backend resolve Stalwart principal và effective permissions. Normal user chỉ thao tác recovery của chính mình; admin/custom role có permission phù hợp mới được quản lý recovery của user khác. Không hard-code duy nhất role === admin.

5. Forgot Password

  1. User nhập account.
  2. Backend resolve principal từ Stalwart.
  3. Lookup recovery email verified trong SQLite.
  4. Sinh OTP 6 số bằng CSPRNG và chỉ lưu hash.
  5. Gửi OTP qua noreply@domain.com.
  6. Verify OTP, TTL, attempts và one-time-use.
  7. User nhập password mới.
  8. Backend cập nhật password trong Stalwart.
  9. Revoke challenge còn hiệu lực và ghi audit.

Public response phải generic để chống account enumeration.

6. Recovery Enrollment

Logged-in User
  → Enter recovery email
  → Send verification OTP
  → Verify OTP
  → verified_at = now

Recovery email chưa verified không được dùng để reset password. Thay đổi địa chỉ phải xóa trạng thái verified cũ.

7. SQLite

Database: /data/recovery.db. Drizzle ORM. Bật WAL, foreign keys và busy timeout.

PRAGMA foreign_keys = ON;

10. Security

  • Không lưu password mailbox trong SQLite.
  • Không expose privileged Stalwart credential/token ra browser.
  • Integration credential dùng least privilege.
  • OTP dùng CSPRNG, chỉ lưu hash, TTL mặc định 15 phút, max 5 attempts.
  • Resend cooldown mặc định 60 giây và rate limit theo IP + account.
  • Session cookie HttpOnly/Secure/SameSite và CSRF protection.
  • Không log password, OTP plaintext, SMTP password hoặc Stalwart secret.
  • Production bắt buộc HTTPS.

14. Implementation

  1. Next.js + Docker standalone + Drizzle/SQLite.
  2. Stalwart adapter: auth, principal lookup, authorization, password update.
  3. Session middleware.
  4. SMTP adapter + noreply.
  5. Recovery enrollment + verification.
  6. Forgot Password + OTP + reset.
  7. Change Password.
  8. Recovery Admin + Stalwart permission checks.
  9. Audit, rate limit, security hardening.
  10. Health checks + Compose + GitHub Actions/GHCR.

15. Acceptance Criteria

  • User/password/role không duplicate khỏi Stalwart.
  • Stalwart kiểm soát authentication và authorization.
  • Recovery email phải verified trước khi reset.
  • OTP one-time, expiring, attempt-limited, rate-limited.
  • Password reset end-to-end cập nhật password thật trong Stalwart.
  • Admin chỉ quản lý recovery workflow.
  • SQLite persist qua container restart/update.
  • Một Docker image tái sử dụng được cho server/domain khác bằng ENV.

16. Definition of Done

V1 hoàn tất khi flow enroll recovery → verify → forgot password → OTP → reset password trên Stalwart chạy end-to-end qua HTTPS, dữ liệu SQLite persist, SMTP noreply hoạt động, authorization lấy từ Stalwart và portal không duplicate chức năng mail-admin lõi.
